# Agent 平台功能对标 — Hull 可借鉴清单

> 调研日期：2026-11-07 · 方法：三路并行外部调研（CLI 平台 / 桌面 GUI / 编排工具）+ Hull 本地能力盘点
> 目的：找 Hull（dsh 的 Electron 桌面壳）可效仿的功能，并为后续需求排序
> 约束前提：CON-R001 不 fork/patch dsh 与官方 UI（官方 view 零注入）、CON-R002 不重写 DSH_HOME、CON-R004 只走官方扩展点

---

## 一、结论摘要

1. **纯编排产品正在批量死亡**：Vibe Kanban README 挂 "sunsetting"、Crystal 2026-02 弃用（指向 Nimbalyst）、Terragon 2026-01 关停、AutoGen 已 archived。→ 编排层单独商业化不成立，**嵌进桌面壳/IDE 才是活路**——这正好验证 Hull 的定位。
2. 最值得抄的不是「更聪明的 agent」，而是**工程化体验**：任务尝试、diff 审阅、检查点、审批分级、通知分级、预算护栏、会话浏览。
3. Hull 当前最大空白（按用户价值）：**会话浏览器、任务尝试/多轮重跑、diff 审阅、检查点、预算护栏、通知分级**；这些全部可在壳侧实现，不碰红线。

## 二、功能矩阵（精选，非全量）

| 能力 | 最佳实践 | 代表做法 |
|:---|:---|:---|
| 检查点/回滚 | Cursor / Kiro / Claude Code | 每 prompt 快照、时间轴预览、只回文件不回消息；Kiro 支持 rewind 分叉会话 |
| 会话 fork | Claude Code / Copilot CLI | fork 出新 session ID，原会话不动；CLI 还能把子会话合并回父 |
| 会话浏览器 | Gemini CLI `/resume` | 列表带时间/消息数/首条 prompt，就地搜正文、可删可排序 |
| 钩子事件总线 | Claude Code（20+ 事件）/ Gemini CLI | exit code 2 = 阻断、stderr 作理由；可触发桌面通知/响铃 |
| 三态审批 + 沙箱 | Codex CLI | `on-request/never` × `workspace-write/danger-full-access`，网络默认关 + 域名白名单 |
| 按模式钉模型 | Roo Code / Copilot CLI | 模式各自记上次模型（plan 用便宜、code 用贵） |
| 逐 hunk 审阅 | Zed | 多文件 review 一个特殊 buffer，逐块 keep/reject |
| 内联评论回灌 | Warp / Vibe Kanban | diff 行上留评论，攒批一次发给 agent |
| 任务尝试 | Vibe Kanban | 一个 task 多次 attempt，每次独立 worktree + 分支，历史可对比 |
| Checks 门禁 | Conductor | CI/lint/未解决评论/todos 聚合，未过阻塞 merge |
| 每任务预算 | OpenHands / Devin | `max_budget_per_task`；Devin 每 session 硬上限 + 按 session 归因 |
| Playbook 版本化 | Devin | 版本历史 + 每个 playbook 的 session 数/合并 PR 数 |
| 触发统一 | OpenHands / Terragon | cron/webhook/issue/IM @ 同一 automation 对象 |
| 上下文可视化 | Claude Code | 用量环 + 分类拆分 + `/compact` 主动压缩 |
| 通知分级 | Claude Code / Warp | 只在「没在看该会话」时通知；通知带当前分支名 |
| 命令面板 | Claude Code / Zed | `Cmd+/` 一屏列全部快捷键 |

## 三、Hull 可落地清单（按优先级）

### P0 — 低成本高价值（不碰红线，复用现有模块）

| # | 功能 | 落地位置 | 说明 |
|:--|:---|:---|:---|
| 1 | **会话浏览器 + 全文搜索** | 复用 `src/tokens/adapters/dsh.ts` 的 `~/.dsh/sessions/*.jsonl.zstd` 解析；新页面 + IPC | dsh 会话在壳内不可见；只读浏览不违反 CON-R001/R002 |
| 2 | **通知分级** | `src/notifications/*` + `WindowManager` 焦点态 + 托盘徽标 | 只在该会话/窗口未激活时发系统通知；并行任务一多必须 |
| 3 | **任务尝试（Task Attempt）** | `src/kanban/types.ts` + `src/exec/scheduler/Scheduler.ts`（已有 agentSpec/cwd） | card → N attempts，每次独立 worktree+分支；重跑不覆盖历史 |
| 4 | **diff 审阅 + 接受/拒绝** | attempt 的 worktree 上 `git diff` → 壳内审阅面板 | 「派活 → 执行 → 审阅 → 合并」闭环的关键缺口 |
| 5 | **每任务预算护栏** | `src/tokens` 扫描 + exec 心跳 | token 上限 → 超限暂停 + 通知；要留「提额继续」，不做硬锁死 |
| 6 | **命令面板/快捷键表** | 渲染层 | `Cmd+K`/`Cmd+/`；纯前端 |

### P1 — 中等成本，形成差异

| # | 功能 | 落地位置 | 说明 |
|:--|:---|:---|:---|
| 7 | 检查点时间线 | 影子 git（Cline/Gemini 同款）+ worktree commit | 每轮/每任务快照，可回滚文件（不做「全量撤销」承诺） |
| 8 | Checks 合并门禁 | 看板合并动作前置检查聚合 | lint/test/CI/未解决评论未过 → 阻塞 merge |
| 9 | 内联评论回灌 agent | 卡片/attempt 评论 → 下一轮 prompt | 省掉复制粘贴 |
| 10 | 触发面统一 | `src/workflows` 抽象 automation（cron/webhook/IM/issue） | 现只有手动+cron；统一后接飞书/GitHub 事件成本骤降 |
| 11 | 上下文用量可视化 | dsh 会话文件估算 → 壳内展示 | 展示成本低于解决成本 |

### P2 — 高成本或边界敏感

| # | 功能 | 说明 |
|:--|:---|:---|
| 12 | MCP/插件管理 UI | 配置在 profile 的 `cordis.patch.yml`，壳编辑会碰 CON-R002 边界；建议只读展示 + 引导 |
| 13 | Playbook/prompt 版本化 + 效果指标 | 需长期数据积累；价值高 |
| 14 | 多 agent 角色协作 | 先做可见性（子 agent 独立时间线），再谈协作；Sculptor 自曝同 workspace 抢文件 |

## 四、明确不要抄（有实证的反模式）

| 反模式 | 证据 |
|:---|:---|
| 不可逆回滚 | Windsurf 官方写 revert「currently irreversible」 |
| 两套会话模型 | Cursor 2.0 改 agent 中心后旧聊天只剩兼容，用户要重学 |
| 看板自成体系 | Cline Kanban 是独立 `npx kanban` web 板 → 双入口双状态 |
| 权限弹窗疲劳 | 逐动作确认 → 无脑点允许；应学三档模式（ask/auto/plan） |
| 通知不分级 | 并行 agent 一多，每个完成都弹 = 噪音 |
| worktree 当安全边界 | Conductor 文档：「development isolation, **not** a security boundary」 |
| 全自动接受开关 | Claude Squad `--autoyes` 标 experimental |
| 硬限流无出口 | Devin 达限后全表面阻塞，只能走申请流程 |

## 五、建议先做

1. **会话浏览器 + 搜索**（P0-1）——数据解析已有，壳最该有而没有。
2. **任务尝试 + diff 审阅**（P0-3/4）——把看板从「派活」升级为「派活→隔离执行→审阅→合并」。
3. **通知分级 + 预算护栏**（P0-2/5）——并行一多必须先有，否则体验先崩。

三者全部在壳侧，复用 exec/scheduler/notifications/tokens 四个现有模块。
