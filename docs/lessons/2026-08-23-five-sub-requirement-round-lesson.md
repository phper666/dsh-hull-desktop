# 五子需求并行交付轮：gitignore 吞源码 / 并行写共享文件竞争 / 传播登记≠落地

> 三硬标准：可复用 / 非显而易见 / 有代价（L1/L2/L3 均通过）
> 来源-出生：五子需求交付轮（dsh-hull-desktop）· 分支 main
> L4（三层核验有效防线）不沉淀：流程本就强制三层，缺「非显而易见」，仅作 L3 佐证。

---

## Lesson 1（L1）：.gitignore 宽泛规则静默吞掉新子系统源码

| 项 | 内容 |
|:---|:-----|
| 场景 | S1 新增 src/skills/ 子系统，按常规「写码 → git add → 提交完成」走完流程。 |
| 坑 | 项目 .gitignore 存在宽泛规则 `/src/**/*.ts`（本意排除编译产物），src/skills/*.ts 被静默忽略——第一次「提交完成」实际是空壳入库。直到 S2 实现时才发现 src/skills 从未 tracked，靠加否定规则 `!src/skills/` + `!src/skills/**/*.ts` 修复。 |
| 代价 | 版本库一度是空壳；交付核验前才暴露，差点带空壳交付。 |
| 教训 | 在 src/ 下新增目录/新文件类型时，先 `git status` 确认新文件真的 tracked（尤其 .gitignore 已有宽泛规则时）；大 commit 前 `git ls-files | grep <新路径>` 验证入库非空。「git add 成功 + commit 成功」≠「文件进了版本库」。 |
| 适用范围 | 任何新增子系统/新目录/新文件类型的仓库，尤其 .gitignore 含 `**/*.ts`、`*.js` 等宽泛排除规则的；不适用于纯修改既有 tracked 文件。 |
| 来源 | 出生：S1→S2 交付轮；证据：.gitignore line 10-20（`/src/**/*.ts` 与 `!src/skills/` 否定规则对） |
| 引用 | 首次引用：本 lesson 出生（2026-08-23）。自证：90 天内除本行外零新增引用 → 删除候选。 |

## Lesson 2（L2）：并行 fixer 写共享文件的竞争窗口与 WIP 测试卡编译门

| 项 | 内容 |
|:---|:-----|
| 场景 | 一轮需求拆 3 个 fixer 并行 lane，各改各的文档与代码，共享 docs/spec/规则索引.md（各自 append 段落）。 |
| 坑 | ①3 个 fixer 都碰规则索引.md——本轮侥幸无覆盖，但 read-modify-write 竞争窗口真实存在，后写者会丢先写者的段。②src/skills 的先存测试文件（实现未到）一度卡住全量 tsc/test 编译门——test:unit 是 `tsc && ...` 短路链，一个类型错误全绿变全红。 |
| 代价 | 多轮定位才把「编译门红」归因到并行 lane 的 WIP 测试文件，而非本 lane 改动。 |
| 教训 | 并行 lane 两条纪律：①共享文件改动收敛为单写者串行（或按 lane 拆分文件），禁止多 lane 各自 append 同一文件；②新子系统的测试文件与实现同批提交，WIP 测试不得先进工作树——短路链（`tsc && test`）下任何一环红 = 全局红，无法区分是谁引入。 |
| 适用范围 | 任何多 agent/多人并行开发共享仓库的团队流程；尤其共享索引/汇总类文档 + 全量编译门并存的场景。 |
| 来源 | 出生：五子需求交付轮（3 fixer 并行）；证据：test:unit 脚本 `tsc &&` 短路链、docs/spec/规则索引.md 多段 append |
| 引用 | 首次引用：本 lesson 出生（2026-08-23）。自证：90 天内除本行外零新增引用 → 删除候选。 |

## Lesson 3（L3）：契约变更传播「登记」≠「落地」

| 项 | 内容 |
|:---|:-----|
| 场景 | Q-052 要求 startDate 字段传播到 B1 契约，change-propagation 流程走了、变更摘要也登记了。 |
| 坑 | 登记完成 ≠ 目标文件变更完成：B1 契约文件里 startDate 出现次数为 0——传播只做了「记录该传播」，没做「改目标文件」。直到交付核验契约层才暴露。 |
| 代价 | 缺口穿透整个实现期，核验层才兜住；若核验漏掉，下游按旧契约实现即返工。 |
| 教训 | change-propagation 的完成判定必须含目标文件实际变更的显式核验（如 `grep <字段> <目标文件>` 计数 > 0），跨文件传播尤甚。「变更摘要已登记」只是意图记录，不是落地证明。佐证：同一轮三层核验还抓到 S2 toResult 字段缺失、E19 焦点口径、Q-034 分级未落地——同类「登记≠落地」缺口不止一处。 |
| 适用范围 | 一切「清单驱动」的跨文件变更流程：契约传播、规则同步、批量重命名登记表；不适用于单文件直接编辑。 |
| 来源 | 出生：Q-052 → B1 契约传播缺口；证据：B1 契约文件 grep startDate = 0、变更摘要已登记条目 |
