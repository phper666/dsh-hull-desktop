## 三、四个坑（调研核心产出）

### 1. 凭据天然不可移植（最重要）

`connections/connections.json` 的敏感字段经 Electron `safeStorage` 加密（`src/connections/ConnectionsStore.ts:72-83`），密钥绑 OS 凭据：macOS Keychain / Windows DPAPI / Linux kwallet-libsecret。**换机器或换 OS 用户后密文必然解不开**；Linux 无 keyring 时回退 `basic_text`（等于明文混淆，仅防肉眼）。macOS 上 safeStorage 行为还受代码签名一致性影响（Hull 用自签名证书，CON-R-packaging-005）。

→ **把该文件原样拷进备份包 = 无效资产**。两个选项：

- **A（推荐 v1）**：不备份凭据，恢复后在「工作台连接」重填（v1 只有 4 个平台）。最懒、无新密码学面、无口令 UX。
- B（v2）：导出时解密 → 用用户口令 AES-256-GCM 重新加密进包 → 恢复时输口令再落地 safeStorage。代价：口令管理 UX + 弱后端风险提示 + 新加解密代码。

> 本机当前**无 connections.json**（尚未存过凭据），无法实测迁移失败路径。

### 2. notes.dir 可指向任意外部绝对路径

`settings.notesDir` 默认 `<userData>/notes`，可改为任意本地文件夹，且**切换不迁移文件**（`src/main/index.ts:127-141`、`src/notes/NotesService.ts:89-141`）。备份包只能带走默认目录内的笔记；外置目录必须写进 manifest（记录原路径）并在恢复期重定位，否则用户以为"备份了笔记"实际没有。

### 3. DSH_HOME 是红线，但 dsh 数据在那里

dsh 会话/历史在 `~/.dsh`（本机 5.3M，sessions 4.7M），Hull 只读、绝不写（CON-R002，`src/tokens/adapters/dsh.ts:177-178`）。备份 v1 不含 → 换机后 dsh 会话历史丢失。这是**产品决策点**：是否提供"另存一份 DSH_HOME 只读快照"（导出方向只读，不违反"永不重写"红线，但需明确措辞与风险）。

### 4. 运行中备份的一致性

settings / boards / notes / workflows 均为 temp+rename 原子写（拷贝可读到完整文件）；但 `kanban/executions/*.log` 是**追加流式写**（src/kanban/ExecutionEngine.ts:258-271），运行中拷贝可能截断、`boards.json` 也可能在拷贝瞬间处于写入窗口。
→ 建议：备份前先 flush 各 store；若存在执行中的任务，禁用备份按钮并提示"建议退出 Hull 后备份"（v1 最省事）。

## 四、恢复方案（复用本项目既有原子性 idiom，CON-R005）

推荐「启动期替换」：

```
选择备份目录 → 校验 manifest + schemaVersion
  → 现数据整目录 rename 为 <name>.bak-<ts>（预备份兜底）
  → 备份内容换入 userData
  → 启动校验：settings/boards 可解析 + 跑 schema 迁移
  → 失败 → rename 回 .bak-<ts>
```

- 与既有模式同构：`UpgradeExecutor.selfHeal`（src/skills/ops/UpgradeExecutor.ts:156-171）、`SettingsProvider.migrate`（src/settings/SettingsProvider.ts:217-265）、`KanbanStore.migrate`（src/kanban/KanbanStore.ts:277-293）。
- **恢复后必须按 schemaVersion 跑迁移**（旧备份 → 新版本）。
- 整目录替换要求应用未运行：要么"退出后由用户手动恢复"，要么写 `pending-restore` 标记 → 重启后启动早期执行（与 dsh 升级的 staging→替换→验证→回滚同构，CON-R005）。

| 数据 | 依赖 | 处理 |
|:-----|:-----|:-----|

### ❌ 不能迁移（拷了无效 / 不该拷）

| 数据 | 原因 |
|:-----|:-----|
| **connections 凭据** | safeStorage 加密绑机器 + OS 用户密钥 → 新机器解不开；**必须重填**（v1 结论） |
| dsh 本体 / overlay / node / corepack | 可重装（CON-R003/R007），278M+276M+196M+39M |
| dsh 会话历史（`~/.dsh`，4.7M） | CON-R002 红线，v1 不含（待拍板项 3） |
| `token-buckets.json` / `skills/hash-cache.json` / `remote-sig-cache.json` | 派生缓存；token 桶数据源在 DSH_HOME，不迁 DSH_HOME 则无意义 |
| `kanban/executions/*.log` | 派生执行日志（运行中追加，拷贝可能截断） |
| Chromium 缓存 / Local Storage / IndexedDB / GPUCache | 派生 |
| 更新器缓存（userData 外） | 派生（差分更新基础包） |
| kanban 附件**二进制**（当前） | **无数据可迁**：上传/落盘链路未实现——PRD §9（:313）规定落盘 `<userData>/kanban/attachments/`，但 renderer / preload / IPC 通道均无实现（ipc-channels.ts 无 attach/upload），存储层仅接受元数据（KanbanStore.ts:582-593）。实测本机 boards.json 0 条附件引用 + 无 `attachments/` 目录。**未来 P2 落地后：二进制在 userData 内 → backup 全量包应纳入；B5 JSON 导出通道仍不含（引用-only，契约 B5 §导出边界，P2 增强项，异机导入按「附件缺失」占位不阻塞）** |
| dsh 自身附件（`~/.dsh/attachments/`） | DSH_HOME 红线外，v1 不含（与看板附件无关） |

### 跨依赖（笔记 ↔ ticket）

笔记 frontmatter 的 `task` 字段（frontmatter.ts:47,62）指向看板 task id → **两者必须一起迁移**才保留关联：只迁笔记不迁 `boards.json`，关联降级为灰色「未知任务」（CON-R-notes-006 定义的中性降级，不报错、不清洗）；反向只迁看板，任务卡上的笔记角标消失。
