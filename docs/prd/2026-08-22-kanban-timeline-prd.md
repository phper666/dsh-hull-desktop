# Hull Desktop（dsh-hull-desktop）看板时间线/日历视图 PRD

> 版本：v0.2 已定案　|　日期：2026-08-22　|　状态：已发布（U-1~U-5 定案）
> 范围：看板时间线视图（活动流）+ 日历视图（按 dueDate/startDate 排布）+ 新字段 startDate + schema v2 迁移
> 前身：M2 后续规划项（2026-08-19 M2 PRD §12 未列，本次从 deferred M2+ 提升至本期承接）

---

## 1. 背景与定位

**M2 已交付**（2026-08-19 验收）：任务看板——6 态模板列 + 列自定义 + 卡片 CRUD + 状态流转 + 子任务聚合 + 评论/执行记录统一时间线 + 执行模式（manual/auto）+ 持久化（`<userData>/kanban/boards.json`，JSON 单文件 + schema 版本 + 原子写）。

**本期目标**：在看板内新增两种视图——**时间线视图**与**日历视图**，解决"看板按列看状态、但按时间看不了节奏"的问题：

- **时间线视图**：把任务的**活动历史**（创建/执行/评论等）沿时间轴铺开，一眼看清"这周做了什么、每张卡进展到哪"；
- **日历视图**：把任务按**截止日期/计划区间**排进日历格，解决"哪些事本周到期、下周要排什么"的规划视角。

两者复用 M2 已搭好的**多视图状态机**（`kanban.js` 的 `viewNames` + 各 render 函数 + 通用工具栏），属壳内增量功能，不碰 DSH_HOME（CON-R002）、不改官方 UI（CON-R001）、不走 dsh 内部扩展点（纯壳内展示层，CON-R004 相容）。

**核心用户故事**：*"我是用 dsh 看板管任务的开发者，希望除了按列看状态，还能按时间看节奏——知道每张卡什么时候建的、执行过几次，也知道哪些任务本周/本月到期，好安排下一步。"*

## 2. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 程序员（主力） | 回顾活动：时间线看某任务/某段时间做了什么（创建/执行/评论时间轴）；规划节奏：日历看到期任务分布 |
| 独立开发者 | 多任务并行时按时间维度跟踪进度、识别积压与临近到期项 |
| 团队协作成员（后续） | 统一装壳即可用；本期不做多人/共享日历（见 §6） |

## 3. 范围

### 3.1 In Scope

- **时间线视图**：按时间轴展示任务活动流（来源 = 既有数据：任务 `createdAt`、timeline 各条 `createdAt`、execution 的 `startedAt/finishedAt`），**零 schema 变更**。
- **日历视图**：月/周粒度网格（默认月，U-1 已定案），任务按 `dueDate` 落格；启用 `startDate` 后按计划区间显示（可跨格）。
- **新字段 `startDate`**：Task 新增可空字段（ISO 日期字符串，与 `dueDate` 同型），详情面板可编辑。
- **schema v2 迁移**：`KANBAN_SCHEMA_VERSION` 1→2，为老数据补 `startDate: null`，不丢数据。
- **视图接入**：两个视图均进 `kanban.js` 的 `viewNames` + 新增 render 函数，复用现有视图工具栏与切换逻辑（与 Board/List/Archive 合计五视图）。

### 3.2 Out of Scope（明确排除）

- 实时协作 / 共享日历（多用户同步看板日历）。
- 任务自动排期（按依赖/工期自动计算 start/due）。
- 跨看板时间线聚合（多看板为 M2 P2 未落地，本期仅当前看板）。
- 拖拽改期（日历上拖任务改 dueDate/startDate，U-4 已定案：本期不做）。
- 新增 schema 之外的字段（duration/endDate 已定案不新增，区间 = startDate→dueDate，见 U-3）。

## 4. 功能需求

### FR-1 时间线视图（P0）

- 视图入口：视图工具栏新增「时间线」按钮，与 Board/List/Archive 并列（进 `viewNames`）。
- **时间轴聚合**：以时间为轴（垂直），分组展示本看板内的活动——任务创建（`createdAt`）、执行记录（execution `startedAt/finishedAt`）、评论/系统事件（timeline 各条 `createdAt`）；按时间倒序（最新在上）。
- 活动条目：来源任务标题（点击跳转对应卡片详情）+ 活动类型徽标（创建/执行/评论/系统）+ 时间戳。
- 空状态：看板无任何活动时显示引导提示（"暂无活动，创建任务后这里会显示时间线"）。
- 验收：看板有任务活动时按时间倒序正确显示；点击条目可打开对应卡片；无活动时显示空态；**不要求 schema 变更**（纯读既有字段）。

### FR-2 日历视图（P0）

- 视图入口：视图工具栏新增「日历」按钮，与上述视图并列。
- **月视图（默认）**：当月日历格，任务按 `dueDate` 落在对应日格；卡片显示标题摘要，过期任务视觉标记（复用 M2 FR-10 过期标记语义）。
- **计划区间**：任务同时有 `startDate` + `dueDate` → 在区间跨格显示（条带）；仅有 `dueDate` → 单日格显示；仅有 `startDate` → 从 startDate 起显示至当月末尾（未定截止）。
- 月/周切换：提供月/周粒度切换（U-1 已定案：默认月视图 + 周视图可选）。
- 任务点击：打开对应卡片详情（复用 M2 详情面板）。
- 空状态：当月无任务时显示"本月无到期任务"。
- 验收：设 `dueDate` 的任务在对应日格正确显示；过期任务有视觉标记；`startDate`+`dueDate` 任务按区间跨格显示；点击卡片打开详情。

### FR-3 新字段 startDate（P0，随日历视图）

- Task 新增字段 `startDate: string | null`（ISO 日期字符串，与 `dueDate` 同型可空）；createTask/updateTask 支持读写。
- 详情面板：截止日期旁新增「开始日期」日期选择器（可空），编辑即时生效并持久化。
- 无 `startDate` 任务（老数据/未填）行为：日历按 `dueDate` 单日显示，不影响既有功能。
- 验收：详情面板可设/清空 `startDate` 并持久化（重启保持）；未填 `startDate` 任务日历正常单日显示。

### FR-4 schema v2 迁移（P0）

- `KANBAN_SCHEMA_VERSION` 1 → 2；`migrate()` 增加 v1→v2 迁移：为每个任务补 `startDate: null`，其余字段原样保留。
- 迁移失败 → 沿用 M2 兜底（备份 `boards.json.corrupt-<ts>` → 重建默认看板）。
- 验收：用 v1 schema 数据（无 `startDate` 字段）加载 → 迁移成功、任务与时间线完整不丢、版本号升为 2；迁移后重新保存落盘为 v2。

### FR-5 视图接入与切换（P0）

- 复用 `kanban.js` 多视图状态机：`viewNames` 增加两视图、新增 `renderTimeline`/`renderCalendar` 渲染函数、视图工具栏按钮统一渲染。
- 视图状态记忆：当前视图切换即时生效并持久化（重启后保持上次视图，若 M2 已有则沿用，无则不做新增）。
- 验收：五个视图按钮切换正常、各视图渲染独立不串扰；切换无卡顿（切换响应 < 300ms，见 §7 性能）。

## 6. 不做事项（明确不承接）

- **实时协作 / 共享日历**：多用户同步看板日历——依赖多人协作/同步方案（M2 §12 后续规划项，未定案）。
- **任务自动排期**：按依赖/工期自动计算计划区间——依赖子任务依赖图（M2 P2 未落地）。
- **跨看板时间线聚合**：多看板功能未落地（M2 P2），本期仅当前看板内聚合。
- **拖拽改期**：日历格拖拽改期（U-4 已定案：本期不做，后置评估）。

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 复用 | 视图接入走 `viewNames` + render 函数 + 通用工具栏，不新建页面/入口；IPC/存储层零新增（仅 Task 字段扩展） |
| 性能 | 视图切换响应 < 300ms；任务量大（≥ 1000 卡）时时间线/日历渲染**分页/按需渲染**（时间线虚拟滚动或按时间段切片；日历按月渲染当月），不一次渲染全量 DOM |
| 安全 | 数据仅存 userData（不触 DSH_HOME）；无新增 IPC 面（沿用 M2 preload 白名单） |
| 稳定性 | 迁移原子性：v1→v2 迁移失败不破坏原数据（备份兜底，沿用 M2）；`startDate` 非法值丢弃并置 null |
| 兼容 | 与 dsh 升级/回滚正交；老版本 schema（v1）数据可直接加载迁移 |

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| v1 数据无 `startDate` 字段 | 迁移补 `null`，日历按 `dueDate` 单日显示 |
| 任务 `startDate > dueDate` | 以 `dueDate` 为准单日显示，不报错（可加 UI 提示，非阻塞） |
| `startDate`/`dueDate` 为非法日期串 | 丢弃并置 null，不阻塞加载 |
| 当月任务量过大 | 按月渲染 + 分页/按需加载（见 §7 性能） |
| 迁移失败 | 备份 `boards.json.corrupt-<ts>` → 重建默认看板（沿用 M2 兜底） |
| 无任何活动/当月无任务 | 各自空状态提示（FR-1/FR-2） |

## 9. 依赖与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| R1 任务量大时时间线/日历渲染性能 | 视图卡顿 | 按需渲染（分页/按月切片），不一次全量渲染（§7） |
| R2 schema v2 迁移破坏老数据 | 用户数据丢失 | `version` 字段 + 迁移函数（只加字段不动存量）+ 失败备份重建兜底（FR-4） |
| R3 日历粒度与字段范围（U-1~U-3） | 返工 | 已定案消除：U-1~U-3 评审定案（月+周/可空 startDate/不新增 duration·endDate），范围冻结 |

## 10. 验收标准（可测试）

- **时间线**：有活动任务 → 按时间倒序正确显示；点击条目打开对应卡片；无活动显示空态。
- **日历**：设 `dueDate` 任务落在对应日格；过期任务视觉标记；`startDate`+`dueDate` 任务按区间跨格显示。
- **startDate**：详情面板设/清空 `startDate` 即时生效并持久化（重启保持）；未填任务日历单日显示。
- **迁移**：注入 v1 数据（无 `startDate`）加载 → 迁移成功、任务与时间线不丢、版本升为 2、落盘 v2；迁移失败走备份重建兜底。
- **视图切换**：五视图切换正常、渲染不串扰、切换响应 < 300ms。
- 上述各项对应 Playwright e2e + node:test 用例（跟随 M2 测试体系）。
