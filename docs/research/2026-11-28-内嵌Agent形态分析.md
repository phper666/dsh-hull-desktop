# Hull 内嵌自有 Agent — 形态分析与路线

> 日期：2026-11-28 · 决策：用户选择「先搭底盘」（M1 只做壳内可跑 + 可观测，用途后定）
> 依据：dsh-superagent 调研（docs/research/2026-11-06-dsh-superagent-prototype调研.md）+ 平台对标（2026-11-07）+ Hull 本地能力盘点

## 一、三种形态

| 形态 | 做法 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **A. dsh 插件** | 写 dsh bundle（`dsh.bundle` + `cordis.patch.yml`，注入 agents/llm/tools 面），壳内装进 hull profile | 用 dsh 全部现成能力；UI 面板天然出现在官方 Web UI（零注入合规） | 受 dsh 插件 API 与版本窗口约束（superagent 卡 0.2.1.x）；调试在 dsh 侧；需避开其坑（改进程 PATH / 专用 profile / 破坏性安装） |
| **B. 壳侧编排（主线）** | 复用 `ACPProvider`（spawn `dsh acp`，JSON-RPC 会话复用）+ `Scheduler` + `ExecutionEngine/Convergence` + `ApprovalManager`；agent = 角色 prompt + 循环 + 工具策略 | 全在壳内；只依赖稳定 ACP 协议；看板/通知/Token/审批全套观测现成；模型用 dsh 已配置的 | 上限 = ACP 能力面（需实测）；agent 循环自写；不进 dsh 官方 UI |
| **C. 壳自调模型 API** | 主进程直调 GLM/OpenAI | 完全可控 | 破坏「壳 = dsh 的壳」定位；自建 key/计费；重复造 |

**结论：B 为主、A 为辅。** 同一 agent 核心（prompt + 循环 + 工具集）先以 B 落地；将来需要出现在 dsh 官方界面时再把同一核心包成 dsh 插件（A），壳负责安装——插件市场正好是它的第一个自家客户。

## 三、要新建的（B 路线真实工作量）

1. **Agent 定义**：角色 prompt + 工具策略 + 迭代上限 + token 预算 → `<userData>/agents/`，可版本化
2. **Agent 循环**：prompt → 观察 → 决策（继续/完成/失败/请求审批）——唯一真正的新逻辑
3. **UI**：nav 新页「Agent」（对话视图 / 运行历史 / 观测）
4. **门禁**（对标教训，第一天带上）：token 预算护栏 + 通知分级 + 审批三档（拒绝 `--autoyes` 式全自动）

## 六、ACP 能力面实测（2026-11-28，真实 dsh 0.2.2-rc.1，结论已验证）

| 能力 | 实测结果 |
|:---|:---|
| `initialize` | ✅ protocolVersion 1；agentCapabilities：**session close / list / resume**、mcp http；无 image/audio/embeddedContext |
| `session/new` | ✅ 返回 sessionId + `configOptions`（model 分组 select + reasoning_effort off/low/high/max） |
| `--patch` 叠加 | ✅ **关键发现**：spawn 时加 `--patch ~/.dsh/profiles/hull/cordis.patch.yml` 即可让 ACP 看到用户全部 provider 路由（不动任何 profile，CON-R002 友好） |
| 模型面 | ✅ 全路由可选：zhipu / new-api / huoshan-yongyou / huoshan-my2 / **opencode-go（25 个模型）** |
| `session/set_config_option` | ✅ `{sessionId, configId:'model', value:'["route","model"]'}`（注意参数名是 **configId**，非 optionId） |
| `session/prompt` | ✅ 流式 `agent_message_chunk` → `stopReason: end_turn`；实测 opencode-go/deepseek-v4.1-flash 正常回复 |
| **`usage_update`** | ✅ **免费送上下文用量**：每轮回推 `{used, size}`（对标 P1-11 上下文可视化的数据源，现成） |
| `session/request_permission` | 未触发（无工具调用场景）；ACPProvider 已有完整实现 |
| `session/resume/list/close` | 声明支持（sessionCapabilities），未实测 |

**必须避开的坑（已实证）**：
1. acp profile 是空 patch → 不叠加 `--patch` 时模型只有默认 `deepseek-official` 路由（**无 key，prompt 必失败**）
2. 用户凭证在 dsh credentials service（`~/.dsh/.credentials.yaml`：ZHIPU/NEW_API/HUOSHAN×2/OPENCODE_GO）——dsh 自己读取，壳无需传 env；但 **zhipu GLM Coding Plan 已到期**（429），opencode-go 路线可用
3. 帧格式 = NDJSON JSON-RPC（换行分隔）；server→client REQUEST 必须回响应帧

**M1 底盘配方（已可执行）**：
```
spawn(node, [dshEntry, '--profile', 'acp', '--patch', <用户 patch 路径>])
→ initialize → session/new(cwd) → set_config_option(model) → prompt
← agent_message_chunk / usage_update / (tool_call / request_permission)
```
