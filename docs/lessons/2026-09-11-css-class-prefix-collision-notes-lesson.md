# 全局 CSS 下的类名前缀撞车：跨模块样式泄漏

| 项 | 内容 |
|:---|:-----|
| 背景 | 笔记模块搜索框出现「双圈」边框 + 拖宽不回流；两轮修复（改 input 盒模型）无效；深挖发现真凶是通知中心模块 `notifs.css` 的同名类 |
| 决策或坑 | 本壳所有模块 CSS 在 shell.html **全局加载**；通知中心（notifs）与笔记（notes）都用 `.nt-` 前缀——notifs 的 `.nt-search { width:240px; padding:6px 10px }` 泄漏到笔记搜索框：固定宽导致不回流、padding 造成双圈空隙。临时修法 = `#notes` 域内高特异性压制（创可贴）；根治 = **模块类名加唯一前缀**（`.nt-` → `.note-`，全量重命名 notes.js/css/e2e 共 400+ 处）。教训：多模块全局 CSS 应用为新模块选前缀前，先 grep 已有模块的 class 前缀表 |
| 影响 | 不治则撞一个堵一个；泄漏是双向的（笔记样式同样会污染通知中心）；症状离根因极远（双圈 bug 查了两轮才到 notifs.css） |
| 适用范围 | 所有 CSS 全局共享的多模块前端（Electron/SPA 同理）；模块 CSS 独立加载（CSS Modules/shadow DOM）的场景不适用 |
| 来源 | 出生：来源子需求 N2 + 来源 PRD `2026-09-07-notes-prd.md`；引用：`notifs.css`（泄漏源）vs `notes.css`（受害方）；提交 `da9338e`（创可贴）、`5e6ce66`（前缀重命名根治） |
| 引用 | 首次引用：搜索框双圈修复 + 前缀重命名（2026-09-11）；后续复用 +1 |
