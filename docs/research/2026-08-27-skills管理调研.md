## 一、TokenTracker 实现拆解

**定位**：Local-first AI token 用量/成本追踪器，覆盖 31 个 coding tools（含 Claude Code/Codex/Cursor/Gemini/DeepSeek Harness）。形态 = `tokentracker-cli` npm 包（`tokentracker serve` 起 127.0.0.1 本地 HTTP server）+ 三平台 native app（Bar/Win/Linux）+ JetBrains 集成。隐私红线「Never reads prompts」。

### 1.1 Skills 管理（src/lib/skills-manager.js，1383 行）

- **平台目标表 TARGETS（10 个）**：claude / codex / grok / antigravity（多目录 dirs() 契约）/ gemini / opencode / openclaw（读 openclaw.json 定位工作区）/ hermes / **zcode（`manageable: false`——仅进清单和筛选，明确禁止对插件缓存做 sync/delete）** / agents（`~/.agents/skills`，`visible: false` 跨工具共享层）。双契约：单目录 `dir()` 或多目录 `dirs()`。
- **安装流（installSkill）**：GitHub Trees API 取仓库树 → 按 sourceDir 过滤 blob → raw 逐文件下载到 tmp staging → 校验含 SKILL.md → `renameSync` 原子落位 SSOT（`~/.tokentracker/skills/managed/<name>`）→ 对每个选中 target 建 symlink → registry.json 登记（含 `contentHash` + `sourceSignature`）→ append-only activity log（上限 500 条，只记动词+skill 名+targets）。同名冲突按 registry 目录名拒装。
- **更新检测（checkUpdates）**：本地 `hashDirectory()`（SHA-256 全文件，path+content 排序）vs 远端 **git tree API 签名**（`sourceSignatureFromTree`——对子目录内 path+sha 排序后哈希，一次 GET `git/trees?recursive=1` 即得，不 clone 不逐文件拉）。
- **回收站**：`managed/.trash/`，TTL 仅 5 分钟（轻量误删兜底，对比 Hull 30 天/500MB 是更重承诺）。
- **发现/市场**：curated 默认仓库列表（anthropics/skills 等 4 个，用户可增删）+ discover 缓存（fingerprint 失效）；`searchSkillsSh` / `fetchPopularSkillsSh` 走 skills.sh。
- **本地导入**：importLocalSkill 收编用户已有 skill 进 managed SSOT 统一管理。

### 1.2 Skill 用量分析（src/lib/skill-usage.js，267 行）★ 独有能力

- 信号：Claude transcripts（`~/.claude/projects`）里的 `{type:"tool_use", name:"Skill", input:{skill}}` 结构；按 tool_use id 去重（主会话/subagent 同 turn 只计一次）；turn 用量在多个 Skill block 间均摊（每 skill 成本之和 == 触发 turns 成本，不重复计）。
- 设计纪律：READ-ONLY、与 token 解析主链路完全解耦（不动 rollout.js/queue.jsonl——那是该项目文档化的头号 footgun）、按需扫描 + 10 分钟 TTL 缓存、隐私上只有 skill 名 + token 数离开 transcript。
- 产品化输出：`local-api.js` `/functions/tokentracker-skills?mode=usage` 把用量聚合 join 已安装清单 → **「零调用已安装 skill = dead-weight 候选」**推荐删除。

### 1.3 Token 捕获通道总览（调研问题②）

不读 prompts 的前提下按工具分通道解析本地痕迹：Claude transcripts 解析、Codex rollout-parser、Cursor sqlite-reader、ZCode **配额走官方 billing/monitor API**（`zcode-limits.js`：zcode.z.ai plan 配额接口，日志作 fallback）等；另有 grok/openclaw hook 注入捕获、passive-mode 兜底。dashboard = serve 静态托管 Vite 构建产物 + local-api JSON 函数端点。

## 二、ZCode skills 管理机制拆解

- **发现顺序（6 层，先者优先/shadowing 模型）**：显式配置 roots > `~/.zcode/skills` > `~/.agents/skills` > 工作区 `.zcode/skills`（cwd 向上到 repo root，**每层级都算，更深优先**）> 工作区 `.agents/skills` > 启用插件的 skills roots。同层内 `.zcode` 先于 `.agents`。**身份 = 文件路径**：同名 skill 多路径全部被发现但只有发现序第一者加载，其余被 shadow。跳过点前缀目录（`.system` 除外）和 node_modules。
- **格式两档失败模型**：SKILL.md frontmatter 平铺键 `name/description/when_to_use/license/metadata`；有 frontmatter 但缺 name/description 或 description >1024 字符 → **丢弃**；无 frontmatter → 加载但难触发（description 空）。触发靠 description（截 ~250 字符呈现给模型）+ when_to_use，无关键词匹配器——**description 写清「何时用」是可触发性的唯一保障**。
- **禁用模型**：配置级 per-绝对路径 override（`~/.zcode/cli/config.json` / 工作区 `.zcode/config.json` 里 `enable: false`），另有整插件 enable/disable 与 built-ins 抑制列表。与 Hull T-4「移目录真禁用」是两种流派：ZCode 有官方配置开关可拨；多数平台没有，移目录才是通用真禁用。
- **分发**：marketplace 安装 plugin（plugin.json 声明 `skills` 字段，可目录/数组/inline），版本化缓存在 `~/.zcode/cli/plugins/cache/<marketplace>/<name>/<version>/skills/`；配套 skill-creator 制作技能、诊断技能 diagnosing-skills 给出 12 条 pitfall 定位工作流。
- **跨工具约定**：Claude/Codex/Cursor 共享放 `~/.agents/skills/`；要只在 ZCode 内覆盖同名 skill 就放 `.zcode/skills/`。

## 四、可落地借鉴建议

**P0（低成本高收益，直接补现成缺口）**

1. **git tree 签名接入远端哈希梯子**（呼应 CON-R-skills-004 的 Q-034 待办注记）：metadata.source 为 GitHub 仓库时，优先 `GET /repos/{o}/{r}/git/trees/{branch}?recursive=1` 计算子目录签名，替代梯子末级「git remote 临时 clone」的待办——一次网络请求、不落盘、天然反映远端最新内容。阶梯变为：平台 lock → metadata.source(git)→ tree API 签名 → cc-switch → 临时 clone 兜底。改动集中在 UpgradeExecutor/hash.ts，纯增量。
2. **SKILL.md 健康度 lint（触发风险提示）**：借鉴 ZCode 两档失败模型，检查器扫描时顺带标注：缺 name/description（加载即丢）、description >1024（硬失败）、无 when_to_use 或 description 前 250 字符没写触发条件（弱触发警告）。只读零风险，强化「检查器」定位。

**P1（中期增强，需小方案评审）**

3. **Skill 使用量/dead-weight 分析**：TokenTracker 独门能力、且注释明言「专用 skill manager 结构上做不到」——Hull 桌面壳恰好具备常驻进程 + 本地 reading 的位势。先做 Claude transcript 单通道（信号结构简单可靠，同 TT v1 边界），产出「已安装但 90 天零调用」候选删除建议，与检查器升级检测并列为两个 tab。注意 READ-ONLY + 不碰会话正文 + 与 DSH_HOME 用户数据红线（CON-R002：只读扫描不改写）。
4. **effective/shadowed 展示**：ZCode 的 shadowing 事实说明——同名 skill 在多目录下各平台的「谁真正生效」不一致。Hull 当前按 name 聚合并展示多平台徽标，可再进一步：每个平台标注实际加载副本 vs 被 shadow 副本（ZCode 可按其 6 层发现序推演；其他平台按各自约定尽力而为），把 T-5 的聚合展示升级为「生效性视角」。需逐平台确认发现序，作为共识变更走 scan → U 项。
5. **curated 仓库发现源**：在 skills.sh 之外加一小撮默认 GitHub 仓库集（如 anthropics/skills）作为发现源，带 fingerprint 缓存；成本低，与现有 searchRemote 并列。

**P2（观察项/暂不做）**

6. 有官方开关平台的「原生禁用」策略分化（ZCode config enable:false）：T-4 移目录定案先保持，等支持平台确有用户诉求再议——改此语义属于共识级变更。
7. manageable 分级（TokenTracker 对插件缓存类只读目录明确不给写操作）：Hull 对 harness/dsh 平台若涉及缓存类目录，同样应设只读边界（登记到规则索引即可，暂不需实现）。

## 五、边界与不做事项

- 不引入 TokenTracker 的 token/cost 追踪本体（超出 Hull 范围；dsh 用量属 dsh 官方能力域）。
- 不复刻其自实现安装器替代现有 `npx skills add` 通道：两条路线各有取舍（TT 版可控性强但要自己维护 GH API 分页/rate limit/私仓 token；npx 版零维护），当前 Q-036 刚实测落地，先跑稳。
- 本次调研结论仅供 consensus-scan/Q-items 决策输入，未直接改代码。
