# 项目任务盘点必须走载体标识：listTasks 无参 = 全量个人任务，不是项目看板

| 项 | 内容 |
|:---|:-----|
| 背景 | 核对项目未完成项时调 `feishu_list_tasks`（无参），返回里混进一个 2021 年季度会议文档残留的僵尸任务（t100002，source=云文档、tasklists 空）。我误把它列入「项目未完成项」，用户找不到，追问才发现查错数据源。 |
| 决策或坑 | **项目管理工具的任务列表接口（无参）默认返回当前用户全部任务/全租户任务，不是某个项目清单的任务**。项目任务的正确作用域 = 团队配置.md 声明载体（ticket 清单 / q-item 清单的 tasklist_guid），按清单过滤。飞书 `feishu_list_tasks` 无参 = 全量个人任务（含个人待办、文档残留、历史模板），与项目清单是两回事。 |
| 影响 | 误判项目状态（把个人僵尸任务当项目项）、错误汇报、用户困惑「找不到」。团队流程已因这个坑在 story-to-contract 加 Phase 0「项目任务盘点」——从团队配置读载体标识按清单列任务，禁止无过滤全量查。 |
| 适用范围 | 任何用项目管理工具（飞书/Jira/Linear/GitHub）查项目任务的场景；尤其多人共享账号、文档残留多、任务池混入非项目项的环境。不适用单任务已知 guid 的直查。 |

## 教训（可复用规则）

1. **查项目任务前先读团队配置.md「项目载体」段**——拿 ticket/q-item 载体标识，按清单过滤，禁止无参全量查。
2. **返回里出现 tasklists 空 / source 非平台 / 创建时间异常旧的任务** → 大概率个人残留非项目项，不列入项目状态。
3. **工具默认视图 ≠ 项目视图**：list/搜索类接口默认作用域是「当前用户」，项目级数据必须显式限定载体。
