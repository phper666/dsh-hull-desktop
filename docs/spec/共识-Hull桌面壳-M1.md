## 2. 文档结构总览

- **覆盖**：Hull 桌面壳 M1 全部业务面——壳骨架（进程管理/壳框架窗口/托盘/日志）、dsh 运行时管理（捆绑 Node/overlay/首次安装）、双通道升级（dsh npm overlay + Hull electron-updater）、壳设置页、会话状态桥（FR-9）。主窗口形态：壳框架窗口（左侧 Hull 导航栏 + 右侧 WebContentsView 内嵌官方 dsh Web UI，零注入）。
- **适用范围**：仅 Hull 应用自身业务；**不覆盖** dsh 官方业务（会话内容、agent 行为、官方 UI 内部），那些是 dsh 的领域，Hull 只做容器与宿主。
- **不做事项（M1 明确排除）**：任务看板（M2+）；三平台打包（仅 macOS Apple Silicon，代码跨平台友好）；Apple 公证/签名；官方 UI 内的壳集成（L1 插件桥）；多实例/多 profile 管理；dsh 内部业务逻辑的任何修改。

## 3. 模块概述

- **定位**：围绕官方 DeepSeek Harness 的桌面开发工具，纯壳——不 fork/patch/替换 dsh，官方升级自动生效。
- **业务目标**：① 装壳即用（自动装 dsh）；② 壳内完成 dsh 升级与回滚；③ 壳自身可升级；④ 用户数据全程官方化（DSH_HOME 不动）。
- **参与角色**：当前 solo（pm/be/fe/qa = phper666）；用户是唯一操作者。
- **子模块清单**：壳骨架（进程/窗口/托盘）、dsh 运行时管理、升级编排（dsh 通道）、壳自更新（Hull 通道）、壳设置页、会话状态桥插件。

## 4. 业务流程与状态机

### 4.1 启动流程

```
壳启动 → 单实例检查 → 确保 overlay（无 → FR-2 首次安装）→ spawn dsh 子进程
→ 就绪判定（就绪行 + HTTP 探测 200）→ 主窗口壳框架就绪 → WebContentsView 嵌入官方 UI → 可用
失败分支：就绪超时（60s）→ 主窗口失败态（重试按钮 + 日志入口，显示在壳框架内）；dsh 崩溃 → 提示 + 可选重启
首装取消 → 主窗口显示"未安装"引导态（安装按钮，点击重新走安装流程，Q-011）
```

### 4.2 dsh 运行时状态机

> 就绪判定（Q-009 结论）：就绪行出现后探测在固定 15s 窗口内周期重试，成功即就绪；就绪行超时预算 60s 独立计算（与探测预算分离）；探测目标与超时可注入（Q-010 测试用）。

| 状态 | 含义 | 合法迁移 |
|:-----|:-----|:---------|
| idle | 未启动 | → starting |
| starting | spawn 等待就绪 | → ready / failed（子进程非预期退出 → 立即 failed，不等超时） |
| ready | 就绪可用 | → starting（重启）/ failed |
| failed | 启动失败/崩溃 | → starting（重试） |

> stop() 迁移（S1 契约 v0.2 评审修订）：任意状态 stop() → idle；starting 中 stop = 杀进程组 + 清理，不等就绪。

### 4.3 升级状态机（dsh 通道）

| 状态 | 含义 | 合法迁移 | 触发条件 |
|:-----|:-----|:---------|:---------|
| idle | 无升级动作 | → checking | 手动检查 / 自动检查发现新版 |
| checking | 查 registry | → confirm / idle | 有新版本 / 无新版本或出错 |
| confirm | 弹确认框 | → installing / idle | 用户确认 / 稍后再说（当日不再提示，Q-008） |
| installing | staging 安装 | → swapping / idle | 安装完成 / 用户取消或失败（按钮下方失败提示，可重试，Q-002/Q-006） |
| swapping | 停子进程+原子替换 | → verifying / idle | 替换完成 / 失败（残留检测恢复，Q-004） |
| verifying | 新版本重启验证 | → idle（成功）/ rollback | 就绪行+HTTP 探测 / 超时 |
| rollback | 换回 dsh-previous | → idle | 回滚完成 |

冲突行为：升级进行中用户再次触发检查 → 忽略或提示"升级进行中"；升级队列单槽，Hull 通道与 dsh 通道互斥（一个排队时另一个入口禁用）。

**升级时机（Q-003 结论）**：确认后立即升级（直接重启 dsh），不等待当前任务——正在进行的会话会被中断，历史记录不受影响。queued 状态与 FR-9 状态桥已删除。

### 4.4 壳升级流程（Hull 通道）

检查（GitHub Releases）→ 确认（版本+变更说明）→ 下载（进度）→ 提示重启安装 → 用户确认 → 先停 dsh 子进程 → quitAndInstall。失败：按钮下方失败提示，可重新点击（Q-006）。无公证限制：更新后启动可能被 Gatekeeper 拦，弹窗引导放行。

## 12. 后端任务规范

- **DshRuntimeManager**：spawn（捆绑 Node + --expose-internals + web + --profile web + --host 127.0.0.1 + --port 0）→ 解析就绪行 → 守护 → 退出清理（进程组/启动兜底）。参数串以 S1 契约 v0.2 为准。
- **Updater（dsh 通道）**：checking → staging 安装（npm install 到 dsh-staging，可取消）→ 停子进程 → 原子替换（dsh→dsh-previous，staging→dsh）→ 重启验证 → 失败自动回滚。
- **Updater（Hull 通道）**：electron-updater 检查/下载/quitAndInstall；重启前停 dsh。
- **崩溃恢复（Q-004）**：启动时残留检测——dsh 缺失 + staging 存在 → 继续完成替换；dsh 缺失 + previous 存在 → 回滚恢复。
- **单实例**：启动锁，第二个实例唤醒第一个。
- **preload 注入边界**：preload 桥仅挂载壳自有占位页（file: 协议）；官方 Web UI 加载时不挂 preload，官方页面全局零注入（CON-R001）。
- ~~FR-9 状态桥~~ **已删除**（Q-003：升级不再需要会话状态，状态栏显示一并移除）。
