# PRD：笔记 / 文档（notes）

> 状态：草案 v0.3（待评审 → 共识）
> 创建：2026-09-07（v0.2：定位扩展工作+个人双类内容，新增一级目录分类；v0.3：一级目录放宽为**任意层级真实目录树**——纯用户自治展示，纪律改为禁自动归类而非禁层级）
> 需求标识：notes
> 调研依据：Foam/Dendron/Claude Code/Cline/Obsidian 方案扫描 + Hull 内部可复用资产盘点（结论摘要见文末附录）

## 1. 定位

**开发者的笔记区：独立 markdown 笔记模块，覆盖工作笔记（跟需求/ticket 走）与个人经验总结（跟人走）两类内容，与看板任务可双向关联，兼作 dsh agent 可读的上下文。**

- 双类内容，目录树区分：**任意层级真实目录**（树形展示，用户自治）+ frontmatter `type:` 徽章；系统不自动归类、不强制整理纪律
- 数据 = 磁盘上的纯 markdown 文件，Hull 卸载后文件还在，用户可用任何编辑器/Obsidian/agent 打开
- Hull 不碰 dsh（CON-R001）：agent 读笔记是「文件在磁盘上」的自然结果，不做任何注入

## 2. 用户故事

0. 记个人经验：不挂任何任务，写一篇「Electron 打包 mac 签名的坑」放 `经验/` 目录，type=经验——纯个人沉淀
1. 开发中随手记：正在做 M2 看板时快速记一条「Q-017 优雅关停的坑」→ 后续沉淀成 lesson
2. 需求上下文：为某个 ticket 记调研笔记，从看板任务详情能跳到相关笔记，从笔记能反查任务
3. agent 协同：把笔记目录路径喂给 dsh agent 当上下文（用户自己操作，Hull 提供路径复制）
4. 检索：按关键词全文搜索所有笔记

## 3. 功能范围（v1）

| # | 功能 | 说明 | 复用 |
|---|---|---|---|
| F1 | 笔记列表 | 左列表右编辑双栏；按修改时间倒序；**树形目录导航**（可折叠，任意层级真实子文件夹，VS Code 资源管理器心智）+ **type 徽章过滤**（工作/经验/想法）；目录按选中节点筛选，搜索永远全局 | 壳视图机制（view 四态扩展 official/board/notes/settings→nav 插入口） |
| F2 | Markdown 编辑 + 预览 | EasyMDE 编辑、markdown-it+DOMPurify 渲染 | **现有 vendor 栈全复用**（CON-R-editor-001~004 直接适用） |
| F3 | 存储 | `<userData>/notes/*.md`，默认此路径；设置页可改自定义文件夹 | 存储约定 + SettingsProvider 扩展 `notes.dir` |
| F4 | 全文搜索 | 内存索引（启动扫描 + fs.watch 增量），文件名+内容匹配 | 新写（量级几十~几百，纯扫描够） |
| F5 | 任务关联 | frontmatter `task: <ticketId>`，**全程点选交互**：① 笔记侧「＋ 关联任务」→ 搜索型选择器（输入即过滤标题/id，按 updatedAt 倒序，看板名前缀平铺，Enter 选中首个），关联/取消（徽章 ×）均回写 frontmatter；② 任务徽章可点击 → 切看板视图并打开该 ticket 详情；③ 任务详情页「相关笔记：N 篇」行（Q2 定的跳转形态）→ 点击切笔记视图并按 task 筛选；④ **看板卡片角标**：有关联笔记的任务卡片显示 `📝 N` 角标（无笔记不显示），点角标直达第一篇关联笔记；⑤ 任务不存在 → 徽章灰色「未知任务」降级，不可点击不报错 | kanban IPC 反查 + 既有 view 切换/详情打开通道 |
| F6 | 快速捕捉 | 笔记页「新建」按钮（时间戳命名 `2026-09-07-<slug>.md`）；全局快捷键 v2 再议 | — |

## 4. 非目标（v1 明确不做）

- ❌ wikilink `[[...]]` 双链及改名联动（Foam 证实这是最大隐藏成本，v2 视需求）
- ❌ SQLite/FTS 数据库（文件扫描足够；真慢了加可弃索引缓存，不当事实源）
- ❌ 同步引擎 / 云同步 / 协作（交给用户的 iCloud/git）
- ❌ 块编辑器（Notion 式）/ 图谱可视化 / 数据库属性面板——编辑面大且与 markdown 互操作打架，Obsidian 也是靠多年+插件才补齐
- ❌ 自动归类 / 标签体系化 / 拖拽移动（v1）——目录深度是用户自由，系统只忠实展示；整理纪律靠人（Dendron 死因是 schema 强制+自动归类，不是文件夹本身）
- ❌ 回收站/版本历史（v1 删除 = 移 `<userData>/notes/.trash/`，简单恢复即可，TTL 30 天对齐 skills 回收站惯例）

## 5. 关键设计决策（待评审确认）

1. **数据位置**：默认 `<userData>/notes/`（与壳其他数据一致、原子写约定可用），设置页可改任意文件夹（改路径 = 提示迁移/重选，不自动搬文件）。**绝不写 DSH_HOME**（CON-R002）。
2. **事实源 = md 文件本身**，无独立索引文件；索引可随时重建。
3. **分类规则**：目录 = 磁盘真实子文件夹，**任意层级**，树形导航（新建目录/移动笔记 = 手动操作：「+ 新建目录」按钮 + 笔记「移动到…」下拉，v1 不做拖拽）；系统**永不自动归类**；`type:` 徽章（工作/经验/想法，自由文本不枚举锁死）做第二维过滤；搜索永远全局。frontmatter 解析用轻量自写（yaml 子集：平铺 key: value），不引依赖。
4. **IPC**：`notes:list/get/save/delete/search`（沿用 `<module>:<verb><Noun>` 约定 + preload 薄封装）。
5. **安全**：渲染路径强制 DOMPurify（CON-R-editor-002 同标准）；自定义文件夹仅限用户主动选择，无额外白名单。

## 6. 红线

- CON-R002：不碰 DSH_HOME
- CON-R001/004：不注入 dsh；笔记是壳内独立层
- 编辑链路遵守 CON-R-editor-001~006（vendoring、锁版本、DOMPurify、destroy）

## 7. 开放问题（评审时定）

- Q1：nav 入口顺序（建议：dsh web / 任务看板 / **笔记** / 设置）
- Q2：任务关联方向——从任务详情嵌一小块笔记列表，还是只做跳转链接？（嵌 = 侵 boards.json 渲染层，需过变更传播）
- Q3：是否需要「每日笔记」daily note（Foam 惯例，成本低，但 v1 可缓）
- Q4：自定义文件夹时与看板数据的关系（无关系，纯独立）

## 附录：调研结论摘要

- Foam 存活 = 纯 md 文件夹 + 内存索引；Dendron 死于维护范围失控 → 学 Foam 架构，砍掉它的野心
- Claude Code/Cline/Cursor 无笔记 UI，全用 md 文件当 agent 记忆 → Hull 笔记天然兼作 agent 上下文
- Hull 内部：EasyMDE/markdown-it/DOMPurify vendor 栈、JSON 原子写、IPC 模块约定全部现成；壳内无 SQLite，不为笔记引入
- 差异点：笔记↔任务关联（竞品没有）
