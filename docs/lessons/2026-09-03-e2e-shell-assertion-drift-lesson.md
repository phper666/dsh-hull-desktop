# 跨视图 e2e 断言（navOrder）与「加导航视图」强耦合——三个功能上线没人更新，main 的 e2e 悄悄红了

| 项 | 内容 |
|:---|:-----|
| 背景 | tests/e2e/cold-start.spec.ts 的 E2E-01 断言 nav 顺序为硬编码数组。tokens、connections、workflows v1 三个需求各自往 shell.html 加了 nav 项，都没更新该断言——main 上 E2E-01 从 tokens 上线起就红，连续 2 周没人发现（各需求分支只验证自己新增的 e2e，存量 e2e 红被当成「与我无关」）。直到 workflows v2 交付跑全量 e2e 才暴露，一并修复（commit 530db1e）。 |
| 决策或坑 | 「壳级结构断言」（nav 数组/视图清单/菜单顺序）是**全需求共享快照**：任何新增视图/菜单的需求，验收清单必须包含「更新壳级结构断言」，否则断言漂移会沉默地污染主分支的 e2e 基线。检测法：改动 shell.html 导航结构 → `grep navOrder tests/e2e/`；更彻底的做法是断言从 shell.html 派生或集中一处定义，但当前体量下「验收清单检查项」即可。 |
| 影响 | 不这样做：存量 e2e 红→真回归被噪音淹没（狼来了效应），e2e 基线失去护栏价值；每个新需求都可能被上一需求的红测试误伤排查时间。这样做：壳级结构变更与断言更新同 commit 走，主分支 e2e 恒绿成为可信信号。 |
| 适用范围 | 任何「结构快照型」测试断言（nav/菜单/路由表/IPC 白名单清单）；多需求并行、共享壳骨架的项目尤甚。 |
| 来源 | 出生：需求 workflows-v2（2026-09-03，E2E-01/E2E-07 两处存量漂移随本需求顺带修复）；关联：CON-R-theme-004（默认主题改 system 后 E2E-07 的 seed 同理漂移） |
