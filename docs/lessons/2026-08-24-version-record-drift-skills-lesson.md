# 共识版本记录漂移：变更摘要自升版本号但版本记录表没同步（撞号才发现）

| 项 | 内容 |
|:---|:-----|
| 背景 | Skills 检查器模块，Q-034 变更（skills-lock 移除）实现后变更摘要写入「升共识 v1.3」，但共识文档 §15.2 版本记录表仍停在 v1.2。后续关闭 T-5 时我按 v1.3 记版本记录，才发现 v1.3 已被 Q-034 占用 → 撞号。 |
| 决策或坑 | **版本号唯一事实源 = 共识文档 §15.2 版本记录表**，变更摘要里写的「升 vX.Y」只是声明不是登记。变更摘要自称升了版本 ≠ 版本记录表真的加了行。Q-034 变更摘要写了 v1.3 却从未在版本记录表登记，导致：①版本记录跳号（v1.2→v1.4）；②后续变更撞号。 |
| 影响 | 版本号语义混乱，追溯基线版本不可靠（Gate A「文档版本可追踪」失真）；撞号需回改、补录 v1.3 行消跳号，多一轮返工。 |
| 适用范围 | 任何用「变更摘要声明版本 + 共识文档版本记录表登记」双写的团队流程；尤其实现先行、文档滞后的场景。不适用单文件、无版本记录表的简单项目。 |

## 教训（可复用规则）

1. **变更摘要自称升版本号时，顺手核对版本记录表是否已登记**——没登记就是漂移，当场补。
2. **版本记录表连续性是强约束**：跳号 = 有版本没登记，先补历史再递增，禁止空降新版本号覆盖。
3. **实现先行场景（先改代码 → 后补文档）**，文档更新要一次到位：版本号 + 版本记录行 + 变更摘要三者同步，不留中间态。
