原型说明 · M2 任务看板

路线决策：C 混合 看板 UI、任务数据、状态流在 Hull 壳内维护；agent 实际执行通过 dsh 官方扩展点/命令通道接入。 数据存 userData/boards.json（JSON 单文件，可迁移）。多设备同步 M2 不做，导出/导入过渡。扩展点插件随壳分发。

执行通道：ExecutionProvider 抽象层，默认 ACP 实现（壳 ↔ dsh headless agent：JSON-RPC stdio；newSession + prompt 提交；session/cancel 干预；仅已提交文本回写）。独立插件形态时换为进程内 ctx.agents。ACP 执行中提示「ACP headless 执行中…」。

来源模型：timeline.source { type, agentId, provider }，预留多 agent 平台接入；示例 agent 名 dsh·research 带徽标显示。

执行状态机：idle → queued → running → (paused ↔ running / interrupted) → failed/verify → done；cancelled 回到执行发起前状态，interrupted 保留在 running 前状态并允许重执行。

  • 颜色图例：卡片左侧色条 = 优先级（P0 红 / P1 琥珀 / P2 蓝 / 无灰）；列头色带 = 状态列自定义颜色；徽标颜色 = 优先级/执行状态。
  • 子任务跨列：子卡放在自己状态列独立显示（与普通卡同视觉），常驻父引用徽标；父卡进度条跨列聚合，展开列表显示每子卡当前列名。
  • 并行上限：maxParallelTasks 默认 5，设置页可配；只有显式声明无依赖（dependencies 为空）的子任务才可并行，有依赖的串行。
  • 执行模式：自动模式须填「做什么/期望结果/如何验证/上下文（可选）」；手动模式隐藏三字段，提供 AI 结果输入区。
  • 人工干预：详情侧板「执行流程」步骤条 + 动态干预按钮；running→暂停/取消/编辑 AC，paused→恢复/取消，failed→重试，interrupted→以新 AC 重新执行/手动完成/继续原执行，成功/空闲→手动完成/改状态。
  • 执行中修订 AC：running 状态可编辑验收标准；提交后执行 interrupted，timeline 记录 AC 变更 diff；可选择以新 AC 重执行、手动完成或继续原执行（不推荐）。
  • 自定义状态列：顶部「管理列」可增删改列（改名/排序/颜色），默认 6 态模板。
  • 时间线：评论 + 执行记录统一流；agent 来源带 AI 徽标，user 评论无徽标，execution 恒显 AI 标识。
  • 附件：上限在设置页可配（默认 10MB），删除卡片级联清理评论与附件。
  • 拖拽跨列：直接生效并写入 timeline（user 来源）；拖到 Done 时若任务未执行完成或父卡子任务未全部完成会弹窗确认；执行中拖到其它列不终止执行，agent 完成后标注「执行完成，列由人工指定」。
  • 点击卡片展开详情侧板，查看描述、子任务、时间线与干预动作。
  • 使用顶部搜索/筛选快速定位任务；点击「+ 新建任务」创建卡片。
  • 点击「agent」按钮模拟交给 agent 执行：排队中 → 执行中 → 完成/失败，记录写入时间线。
